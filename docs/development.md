# Development guide

## Prerequisites

- Node.js 24 LTS (the exact major is recorded in `.node-version`);
- Corepack;
- pnpm 11 (the package manager is recorded in `package.json`).

No server, database, account, external API, or telemetry service is required.

## First bootstrap

The scaffold intentionally does not include installed dependencies or a hand-made
lockfile. The first maintainer bootstrap is:

```sh
corepack enable
pnpm install
pnpm check
```

Review and commit the generated `pnpm-lock.yaml`. After that, all local and CI
installs use:

```sh
pnpm install --frozen-lockfile
```

Never edit the lockfile manually.

## Command map

| Command | Purpose |
|---|---|
| `pnpm build` | compile all TypeScript project references |
| `pnpm typecheck` | strict TypeScript validation |
| `pnpm lint` | Biome lint rules |
| `pnpm format:check` | verify formatting without writing |
| `pnpm format` | format tracked source and docs |
| `pnpm test` | run Vitest once |
| `pnpm test:coverage` | run tests with enforced coverage floors |
| `pnpm action:package` | bundle the Action entrypoint for Node 24 |
| `pnpm check` | run the complete local verification gate |

## Package workflow

- Put filesystem discovery, evidence, rule, score, and report behavior in core.
- Keep CLI and Action code limited to input/output translation.
- Add a synthetic fixture before fixing a repository-specific false result.
- Prefer Node platform APIs to a dependency. Document why every added dependency
  is needed and inspect its install scripts and transitive surface.
- Do not run commands from a fixture or scanned repository in tests.

## Tests

Unit tests live beside package boundaries under `packages/*/test`. Cross-package
integration and fixture suites will be added with the first schema and discovery
implementation. A rule change must cover pass, partial, fail, malformed, and
adversarial input.

Tests must use temporary directories or files under `fixtures/`; never use a
developer's private workspace as input. Network access is forbidden in core
tests and should be disabled explicitly when a test harness is introduced.

## Generated Action bundle

`packages/action/dist/index.cjs` is generated by `pnpm action:package`. It must be
committed for a release tag because GitHub executes the checked-in bundle. CI
must rebuild it and verify that the committed bundle is current before the first
Action release.

## Private local handoff

Copy `AGENTS.local.md.example` to the ignored `AGENTS.local.md` when Codex needs
a bridge to private planning notes. Never add absolute local paths or private
note content to tracked documentation.
